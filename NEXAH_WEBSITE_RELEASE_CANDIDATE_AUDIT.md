# NEXAH Website Release-Candidate Audit

## ✅ Ready

- **Reproducible candidate:** The documented verification command against the frozen ORION revision completes successfully: 55 of 55 tests pass, Astro reports 0 errors, 0 warnings and 0 hints, 206 static pages build, the internal-link checker reports no broken links, and `git diff --check` is clean.
- **Internal navigation:** All 206 generated pages resolve through the built-site link check. The primary navigation has distinct destinations, current-page state, desktop and mobile presentations, and no detected internal dead end.
- **Footer coverage:** Home, Visitor Guide, Laboratory, Library, Atlas of Atlases, About, Contact, Accessibility, Privacy and Imprint expose the same footer routes for Contact, Accessibility, Privacy and Imprint.
- **External repository routes:** The public NEXAH, ORION and NEXAH Experience repositories, the security policy and the licensing record respond successfully.
- **Core metadata:** Every generated page has a title, description, canonical URL and document language. Canonicals consistently use `https://nexah.de`.
- **Indexing fundamentals:** `robots.txt`, `sitemap-index.xml`, the generated sitemap and the favicon are present. The sitemap contains all 206 generated routes. HTTP and `www` requests permanently redirect to `https://nexah.de/`.
- **Images:** Reviewed images have alternative text and intrinsic dimensions. Local Atlas images and external Are.na covers load successfully after lazy content enters the viewport.
- **Responsive foundation:** The site has explicit desktop, tablet and mobile rules, keyboard-visible focus treatment, a skip link, reduced-motion support and responsive-navigation tests. No horizontal overflow was found on the reviewed principal routes.
- **Visual system:** The cream, navy and ochre system, typography, spacing tokens and hierarchy are consistently applied across the reviewed public entrances and legal pages. The site deliberately uses one light editorial theme; no contradictory dark-theme state exists.
- **Accessibility disclosure:** The Accessibility page accurately describes current support, names known limits, provides a barrier-reporting route and does not claim formal statutory conformance.
- **Contact and licensing:** `contact@nexah.de`, Haptikdesign GmbH and the Frankfurt address are consistent across Contact, Imprint and Privacy. The repository clearly distinguishes Apache 2.0 software licensing, CC BY 4.0 original documentation and visual material, and retained third-party rights.

## ⚠ Needs attention

- **Social previews:** Open Graph and Twitter title, description and URL metadata exist, but no page supplies `og:image` or `twitter:image`. Shared links will not have a controlled visual preview.
- **404 experience:** No repository-owned `404.astro` page exists. Unknown routes therefore depend on the host’s generic error response and do not provide a calm return to NEXAH.
- **SEO title collisions:** Concept and theme pages reuse titles for Cartography, Language, Perspective, Representation and Wonder. Two Mathematica IV publication routes also expose the same publication title. These do not break navigation, but they weaken search-result distinction and may represent duplicate publication content that needs an explicit canonical or redirect decision.
- **Primary terminology:** The Visitor Guide and current homepage copy present NEXAH as the Orientation Ecosystem, while the default document title and About page still define it primarily as “Orientation Cartography.” The About phrase “One place” also conflicts editorially with the Visitor Guide’s “Four places.” Confirm the canonical public wording and use Orientation Cartography as a supporting discipline rather than an accidental competing identity.
- **Image payload:** `public/` is approximately 30 MB. The largest Library images are approximately 408 KB, 532 KB and 816 KB, and many generated reader images do not declare an explicit loading policy. The principal pages loaded correctly in the audit, but noncritical imagery should be checked once more against the final production network waterfall.
- **Editorial language:** The public copy is generally clean, but English style is mixed: for example, British “enquiries” appears beside US-oriented metadata and wording. Select one editorial English convention for the final copy pass.
- **Heading outline:** `/orientation/` contains several step-level `h1` elements in mutually hidden panels. Only one is visible during interaction, so this is not a functional blocker, but the final accessibility pass should confirm the intended document outline with assistive technology.
- **Repository onboarding:** The README correctly links governance, licensing and canonical owners, but it does not point directly to a canonical Manifesto or Public Release Claim. If those are part of the launch set, add references rather than duplicating their content.

## ❌ Must fix before launch

- **Deploy the audited candidate:** The live `https://nexah.de/` is not the audited local candidate. It still exposes the earlier Explore navigation, lacks the new Visitor Guide entrance and uses the older footer without Accessibility, Security and Open Source links. Publish the exact verified candidate revision, then repeat the production smoke test.
- **Restore or remove the NEXAHEDRON destination:** `https://nexahedron.com/` and `https://nexahedron.com/privacy/` were unreachable during two independent checks, while Home, Visitor Guide, the ecosystem map and README direct visitors there. Either deploy and verify NEXAHEDRON before launch or remove the public calls to action until the destination is available.
- **Adopt the approved bilingual legal layout:** Imprint and Privacy are currently German-only. Before launch, make each a single bilingual document with English first and German immediately below, marking the language of each section explicitly. Use the same canonical pages for the project instead of maintaining divergent copies.
- **Complete deployment-specific privacy facts:** The Privacy Policy describes generic server logging but does not identify the selected hosting provider, server location, recipient categories or the actual log-retention period. These facts must be supplied from the final hosting configuration and reviewed against the deployed behavior before publication.
- **Confirm legal operator facts:** The owner must verify the commercial-register information and confirm whether Haptikdesign GmbH has a VAT identification number or business identification number that must be disclosed. Confirm separately whether a data-protection officer is appointed. Do not infer these facts in the repository.
- **Align repository release status:** The README says `nexah.de` is publicly deployed and shows a live badge, while `SECURITY.md` calls the project a pre-release website with no production release. Set one accurate Version 1 status across README, Security, publication baseline and repository metadata at the moment the candidate is released.
- **Run the final production gate after deployment:** Verify HTTPS and redirects, all principal routes, legal/footer links, external images, mobile navigation, the Orientation journey, browser console, final canonical URLs, sitemap contents and a controlled message to `contact@nexah.de` against the deployed revision—not only the local preview.
- **Launch decision:** The audited source candidate is technically releaseable, but the public launch is **NO-GO** until the stale deployment, unreachable NEXAHEDRON links and unresolved legal/hosting facts above are closed.
