# Orientation Interface

## Purpose

Sprint 06 lets a visitor bring one real question without presenting NEXAH as a
chatbot or implying that arbitrary language can already be executed by ORION.

The interface is an orientation instrument with a visible boundary:

```text
Visitor question
       ↓
explicit confirmation
       ↓
existing language boundary
       ├─ registered canonical request → existing ORION report
       └─ unsupported wording → visible translation boundary
```

The static build-time integration from Sprint 02 remains unchanged. Sprint 06
does not add browser-to-Python transport, a new translator or a reasoning loop.

## Visitor intent

The visitor owns the wording and may enter any honest question, including a
question the current deterministic architecture cannot yet translate. Accepting
the question is not a promise to answer it.

The interface offers one bounded action at a time:

1. write one question;
2. confirm the exact wording;
3. inspect whether an existing deterministic request is available;
4. examine the resulting report or the unsupported-language boundary;
5. continue independently or leave.

There is no message history, conversational persona, automatic follow-up or
open-ended response generation.

## Question lifecycle

### 1. Entry

The question is entered on Home or directly on the Orientation page. The
Experience enforces only a length boundary; it does not classify the subject.

### 2. Confirmation

The visitor sees the exact text before orientation begins. No source
Representation, target, publication or concept is inferred during this step.

### 3. Session

After confirmation, the question is held in `sessionStorage` and in the URL of
intentional journey links. This keeps it visible across the static Experience
without an account, server, database or durable profile.

The session belongs to one browser tab. The visitor can end it explicitly. The
question is then removed from local session state and from the current URL.

### 4. Deterministic boundary

The Experience compares the trimmed wording exactly with the one canonical
request already generated by the frozen Sprint 02 build integration. This is a
bounded identity check, not natural-language interpretation.

- An exact supported request opens its existing `TransformationReport` and
  `LyraExplanation`.
- Any other wording stops before ORION planning and shows a language boundary.

Unsupported wording is never replaced by the canonical request.

### 5. Continuation or departure

A supported report may enter the existing explicit Sprint 05 editorial path.
An unsupported question receives no publication recommendation. The visitor
may instead enter the Library or Atlas independently, edit the question, or
leave.

## Authority boundaries

| Layer | Owns | Does not own |
|---|---|---|
| Human | question, interpretation, continuation, departure | ORION status or evidence |
| Experience | capture, confirmation, transient session state, presentation | translation, planning, evidence, recommendations |
| LYRA | the already registered canonical translation and explanation | arbitrary Sprint 06 language |
| ORION | the existing deterministic plan, report, validation and blockers | natural-language interaction |
| Library | publication metadata and editorial content | report evidence or inferred recommendations |
| Living Atlas | explicit registries and curated relations | semantic matching or inferred edges |

## Clarification philosophy

Clarification is optional and finite. In Sprint 06 it means returning to the
single question field and editing the wording before another bounded check.

Clarification is not a conversation. The Experience does not ask leading
questions, offer generated paraphrases, infer intent or negotiate meaning. A
future conversational boundary would require separate architectural authority
and is not introduced here.

## Transparency principles

At every boundary the visitor can distinguish:

- **My question** — shown verbatim in the session ribbon and orientation view.
- **What the Experience did** — preserved wording and checked an existing exact
  request boundary.
- **What ORION did** — either produced the existing deterministic report or was
  not invoked for unsupported wording.
- **What belongs to the Library** — independent editorial reading, never report
  evidence by proximity.
- **What belongs to the Atlas** — registered identifiers and explicit curated
  relations, never semantic recommendations.
- **What remains unknown** — the missing mapping from unsupported language to
  an existing Orientation Object and Representation Target.

## Current limitation

The first orientation instrument accepts every question but can execute only
the exact canonical LYRA request already proven in Sprint 02:

> I want to understand how this observation reaches the calendar.

This limitation is made visible by design. Expanding language coverage or
adding runtime transport requires future authorized work outside Sprint 06.

## Explicit exclusions

Sprint 06 introduces no LLM, provider, runtime service, API, embeddings,
semantic search, hidden ranking, inferred Library recommendation, Atlas edge,
account or durable persistence.
